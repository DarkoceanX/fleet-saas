## Поведение и границы

- GET отчёта без `page_size` совместим с прежним полным ответом. UI использует
  `page_size=20`, а продолжение — GET `/period/entries` с kind, limit, offset,
  expected_revision. Суммы, ставки, предупреждения и полнота считаются по полному
  периоду до выбора страниц. Доходы не уменьшают себестоимость.
- Даты сортируются по возрастанию, одинаковые даты разрешаются ID. Чтение и проверка
  revision проходят под существующим tenant lock; изменение данных требует нового
  отчёта (409), а не продолжения по изменившемуся набору. Tenant/roles не расширены.
- UI показывает количество загруженных строк и отдельные кнопки догрузки.
  Одновременный повтор страницы блокируется. Поздние ответы после обновления,
  мутации, смены машины/периода и unmount не применяются. Ошибка текущей страницы
  позволяет повторить её, конфликт revision требует обновить отчёт.
- Редактор признания может догружать ручные расходы для замены. Выбранная запись
  сохраняется вместе с исходной version даже вне первой страницы после обновления.
  Сервер остаётся арбитром устаревшей версии/удаления; неизвестный исход POST
  сохраняет ключ и тело повтора. Смена машины/периода закрывает прежнюю форму.
- Сервер по-прежнему читает полный набор для Decimal-агрегатов. Показания,
  непризнанные источники и сведения о признании за другой машиной не разбиваются
  на страницы. Оптимизация SQL/памяти и нагрузочные гарантии не входят в этот этап.

Полный [контракт](API.md#страницы-детализации-периода-01112026).
