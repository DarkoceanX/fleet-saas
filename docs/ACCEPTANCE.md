# Проверки перед использованием

## Комплект

- Свежая распаковка проходит `python scripts/check_starter.py --integrity`.
- Найдены ровно шесть SKILL.md с различимыми сценариями применения.
- Тесты калькулятора проходят, пример даёт 23980.00 RUB себестоимости.
- `.env` не попадает в Git; `.env.example`, config и skills отслеживаются.
- В Codex проверены корень проекта, доступные навыки и активные инструкции.

## Будущий MVP

Исходная таблица требований. Текущее фактическое покрытие см. в
[VERIFICATION_STAGE_2](VERIFICATION_STAGE_2.md) и [VERIFICATION_PERIOD](VERIFICATION_PERIOD.md).
Проверки export/фоновых задач/восстановления не объявляются выполненными без реализации.

| Сценарий | Ожидаемый результат |
|---|---|
| Пользователь tenant A запрашивает ID машины B | Данные и факт существования не раскрываются |
| A назначает на свой рейс водителя B | Отказ API и ограничение БД |
| Viewer изменяет затраты прямым HTTP-запросом | Отказ независимо от состояния кнопки |
| Повтор POST расхода после таймаута | Одна запись и один денежный эффект |
| Одновременное редактирование рейса | Контролируемый конфликт version |
| Изменение тарифа после завершения рейса | Старый расчёт сохраняет снимок |
| Нулевой пробег или выручка | Нет деления на ноль; понятное отсутствие метрики |
| Экспорт или фоновая задача для другого tenant | Доступ отклонён |
| Сбой новой миграции | Известное состояние и проверенная процедура восстановления |
| Ошибка API в интерфейсе | Понятное сообщение, введённые данные не потеряны |

Приёмка первой вертикали: создать организацию с двумя ролями, машину и рейс,
рассчитать план, сохранить детализацию, прочитать его с допустимыми правами;
другой tenant результата не видит. Все fixtures синтетические.
