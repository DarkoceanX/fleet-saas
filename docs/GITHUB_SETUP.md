# GitHub: от архива к проверяемой задаче

Команды ниже выполняются пользователем в новой внутренней папке пакета.
Не запускайте `git init` внутри существующего рабочего репозитория без необходимости.

```text
git init -b main
git add .
git diff --cached --stat
git diff --cached
git commit -m "Add Fleet SaaS hybrid Codex starter"
```

До коммита просмотрите индекс: там не должно быть `.env`, ключей или данных
клиентов. `.env.example` и `.agents/skills` должны попасть в Git.
Создайте пустой приватный репозиторий на GitHub без отдельного README.
Замените OWNER и REPO на свой путь:

```text
git remote add origin https://github.com/OWNER/REPO.git
git push -u origin main
git switch -c feat/first-fleet-slice
```

Это инструкции, а не выполненные операции: новый GitHub-репозиторий этим архивом
не создаётся. Если remote уже настроен, проверьте `git remote -v` вместо повторного
добавления. Если сервер не пустой, сначала получите его историю и согласуйте файлы.

## Проверки PR

Workflow `starter-checks.yml` запускает проверку комплекта и тесты на push/PR
в main. У него только чтение содержимого, нет production secrets и deploy.
В настройках защиты main включите PR и обязательный status check
`Starter checks / starter` после первого успешного запуска. Название в интерфейсе
проверьте по фактическому прогону; доступность правил зависит от аккаунта.
Добавьте запрет force push, если это поддерживается выбранным репозиторием.

При создании приложения расширьте CI его lint, typecheck, unit/integration,
build и критическим E2E. Зелёный starter-checks не проверяет отсутствующий SaaS.
Для реального релиза нужны тестовое окружение, миграции, проверка изоляции,
план отката и отдельные права среды. Используйте шаблон PR из `.github`.

## Цикл изменения

Задача → отдельная ветка → реализация → локальные проверки → commit/push → PR →
CI и ревью → merge в рамках выданных полномочий. Не коммитьте токен GitHub;
вход выполняется штатным механизмом Git/Codex. Для облачной задачи передавайте
ветку и commit SHA, ожидаемые файлы, критерии и реальные команды проверки.
Возвращайте ссылку PR и фактические результаты; порядок описан в HYBRID_CODEX.md.
