## Подтверждённое направление и текущая реализация

| Область | Текущее положение |
|---|---|
| Продукт | SaaS для собственного/привлечённого корпоративного парка и владельцев малого парка: автомобили, грузовики, спецтехника. Это продуктовый охват, не утверждение о готовности всех сценариев |
| Два уровня | Рейс: план, цена, маржа, фактические операции; техника за период: признанные расходы/доходы и отдельный финансовый результат |
| Стек | Локальные TypeScript, Next.js, NestJS, PostgreSQL; модульный монолит. Архитектурные схемы будущих сервисов не означают их наличие |
| Деньги | В текущих контрактах RUB/Decimal; единицы, масштаб и округление задаются соответствующей формулой |
| Источники | Рейсовой расход включается в период ссылкой; доход имеет единый первичный реестр. Плановая выручка не превращается в факт автоматически |
| Полнота | Неизвестно, частично внесено, подтверждено и подтверждённый ноль различаются; изменения инвалидируют проверки по действующему контракту |
| Выработка | Км, фактические рабочие часы и моточасы двигателя независимы; себестоимость не уменьшается на доходы |
| Текущие права | Owner/dispatcher изменяют операционные данные; все роли читают разрешённые операционные данные; финансы доступны owner/accountant. Управления членством нет |
| Гибридная работа | Локальная/облачная работа через GitHub — целевой процесс. Текущая папка передана без Git; источник фиксируется путём и хешами до отдельной настройки версионирования |
| Рабочее включение | По передаче 24.10 миграции 003/004 не применены к рабочей БД. Актуальную схему и сборку проверять отдельно, не выводить из наличия исходников |
| Ориентиры | Завгар Онлайн — функциональный ориентир, Yoolip — визуальный; без копирования и без автоматического переноса их бизнес-правил |

## Что требует отдельного решения

- Правила распределения общих/постоянных затрат и одного источника между машинами.
  Сейчас вводятся признанные доли вручную с основанием; автоматического распределения нет.
- Окончательная бизнес-матрица ролей, управление участниками и расширение доступа к финансам.
  До решения действуют существующие ограничения, а не открытый доступ.
- Источники пробега/топлива, импорт и интеграции, история владения и замена счётчиков.
- Другие валюты, FX, налоги, счета/платежи и бухгалтерские интеграции.
- Сроки хранения, масштаб парка, нагрузочные цели, провайдер, бюджет, RPO/RTO и эксплуатация.

Порядок текущих исправлений уже задан финансовыми контрактами: не объявлять его
неопределённым и не унифицировать разные возможности расхода/дохода без новой задачи.
Телеметрия, оптимизация маршрутов, платежи и AI-функции отложены. Python остаётся
эталоном расчёта рейса и проверкой комплекта, отдельного Python-сервиса нет.
Исторические результаты и следующий ограниченный шаг: [CODEX_HANDOFF](CODEX_HANDOFF.md).
