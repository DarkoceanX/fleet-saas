# Локальная настройка

Для проверки пакета нужны Python 3.11+ и, для истории изменений, Git.
Для запуска Codex используйте установленное приложение или CLI и войдите
в свой аккаунт. Наличие доступа к облачной среде проверяется отдельно.

## Windows

Распакуйте в новую папку. Например, при выбранном размещении:

```powershell
Set-Location 'D:\Logistic\fleet-saas-hybrid-codex-starter'
python --version
python scripts/bootstrap.py
python scripts/check_starter.py --integrity
python -m unittest discover -s tests -v
python scripts/calculate_trip.py examples/trip-cost.json
```

Если `python` не найден, используйте доступный Python Launcher `py -3` вместо
`python` и проверьте версию. Bootstrap ничего не скачивает и не запускает сервисы.
Он проверяет структуру и запускает тесты. В Linux/macOS используйте `python3`.

## Настройки Codex

Откройте внутреннюю папку комплекта как проект. Репозиторные навыки обнаруживаются
в `.agents/skills`; каждый содержит `SKILL.md` с name и description.
Если они не появились, проверьте корень проекта и перезапустите Codex.
В CLI можно открыть `/skills`. [Источник](https://learn.chatgpt.com/docs/build-skills).

Проектный `.codex/config.toml` применяется для доверенного проекта. В нём
`workspace-write`, `on-request` и выключенная исходящая сеть команд.
Модель остаётся выбранной в аккаунте. Настройки организации могут иметь приоритет;
не отключайте их ради шаблона. [Источник](https://learn.chatgpt.com/docs/config-file/config-basic).

Запрос для проверки: «Перечисли применённые инструкции проекта и шесть навыков.
Ничего не изменяй. Укажи, какие проверки здесь реально доступны».
`AGENTS.md` читается как проектная инструкция; проверьте также родительские и
глобальные override-файлы. [Источник](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

## Окружение будущего приложения

`python scripts/bootstrap.py --create-env` создаёт `.env` из примера только при
отсутствии файла, существующий файл не перезаписывает. Сейчас калькулятор `.env`
не использует. При реализации приложения добавьте проверку обязательных полей
на старте и загрузку окружения выбранным фреймворком. Не выполняйте `.env` как скрипт.
Dev-секреты должны быть отдельными от production. Пустой SESSION_SECRET нельзя
заменять запасным фиксированным секретом в коде.

Если проект уже существует, перенесите файлы выборочно и согласуйте AGENTS.md,
Git ignore, настройки и CI с текущими. Не заменяйте глобальный config.toml.
Проверка manifest предназначена для свежей распаковки и ожидаемо перестанет
проходить после редактирования файлов; обычная проверка структуры остаётся полезной.
