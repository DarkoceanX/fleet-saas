# Гибридная работа Codex

Гибрид здесь означает два места выполнения при одной истории Git:
локальный компьютер для интерактивной работы и облачная среда для изолированных
задач. Это не отдельный параметр hybrid=true и не автоматический запуск шести агентов.

| Работа | Предлагаемое место | Передаваемый результат |
|---|---|---|
| Уточнение UX, просмотр экранов, локальные интеграции | Локально | Код, снимки, проверки |
| Ограниченный API/тестовый рефакторинг | Локально или Cloud | Ветка/PR с доказательствами |
| Воспроизведение CI и обзор изменения | Изолированная среда | Логи проверки и замечания |
| Действия с production | Отдельная среда с нужными правами | План и разрешённый выпуск |

GitHub — источник версий, а не механизм передачи некоммиченных файлов.
Перед началом определите исходный commit, ветку и область задачи. Не выполняйте
одновременные независимые правки одних файлов в одной рабочей копии.

## Настройка текущей Cloud-среды

Выберите Work in → Cloud → Create environment, подключите нужный репозиторий.
Для этого starter запросите Python 3.11+ и запуск `python3 scripts/bootstrap.py`.
Просмотрите отчёт настройки и опубликуйте среду, затем проверьте новую задачу.
Сохранение и публикация среды различаются; после изменения подготовки нужна
повторная публикация. Доступность зависит от аккаунта.
[Официальная инструкция](https://learn.chatgpt.com/docs/environments/cloud-environments).

Для задания используйте templates/TASK.md. Передайте точный commit и попросите
сначала сверить `git rev-parse HEAD`. Не предполагайте, что новая задача получила
локальные изменения или нужную ветку автоматически. Разрешайте только необходимые
сетевые назначения и dev-учётные данные через механизм секретов среды.

Старый Codex Cloud для Code Review и интеграций описан отдельно как Legacy;
не переносите его настройки и жизненный цикл секретов на текущую среду.
[Legacy-справка](https://learn.chatgpt.com/docs/environments/cloud-environment).
Проектный TOML локальной работы не является полной политикой облачной среды.

## Возврат в локальную работу

Получите commit/PR, прочитайте diff, затем перенесите ветку штатным Git-процессом.
Не переключайте рабочую копию поверх несохранённых пользовательских изменений.
Повторите относящиеся к изменению интеграционные проверки в целевой среде.
Передавайте краткий отчёт по templates/HANDOFF.md: сделано, commit, проверки,
ограничения, миграции, следующий шаг. Не пересылайте весь чат и секретные логи.

Если Cloud недоступен, тот же ограниченный task выполняется локально в отдельной
ветке; CI на GitHub остаётся общим местом проверки. Автоматическое слияние и
автоматическое развёртывание этот starter не настраивает.
