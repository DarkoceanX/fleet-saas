# Fleet SaaS — hybrid Codex starter

Новый комплект конфигурации от 24 октября 2026 года. Это основа для разработки
SaaS управления автопарком: инструкции агента, шесть навыков, архитектура,
расчёты и настройка локальной/облачной работы через GitHub.

В starter реализована локальная основа: Next.js, NestJS и PostgreSQL,
вход, организации и роли, машины, водители, назначения, статусы рейсов,
плановая себестоимость, фактические расходы и сравнение план/факт.
Инструкция запуска, тестовые входы и ограничения: [RUNBOOK](docs/RUNBOOK.md).
Контракт API: [API](docs/API.md). Решения этапа: [FIRST_SLICE](docs/FIRST_SLICE.md).
Результаты локальных проверок и экран приложения: [VERIFICATION](docs/VERIFICATION.md).
Решения второго этапа: [SECOND_SLICE](docs/SECOND_SLICE.md).
Добавлен расходный подэтап «Техника → Период → Себестоимость»:
[правила и границы](docs/VEHICLE_PERIOD.md), [проверки](docs/VERIFICATION_PERIOD.md).
Реализованы [фактические доходы рейса/машины и отдельный финансовый результат](docs/RECOGNIZED_INCOME.md).
Плановая цена не считается фактической выручкой; себестоимость остаётся до вычета доходов.
Миграции 003/004 подготовлены и проверены изолированно, к рабочей БД не применялись.
28 октября 2026 обновлены существующие шесть навыков и инструкции разработки под
оба уровня финансового учёта; код приложения и эталонный Python-калькулятор не менялись.
Разделы ниже описывают исходную поставку. Публичного размещения нет.
Текущее состояние и границы проверки: [CODEX_HANDOFF](docs/CODEX_HANDOFF.md).

## Начало за пять шагов

1. Распакуйте ZIP в новую папку. Внутри будет `fleet-saas-hybrid-codex-starter`.
   На Windows можно выбрать `D:\Logistic\fleet-saas-hybrid-codex-starter`.
   Не распаковывайте поверх действующего проекта без просмотра различий.
2. Откройте внутреннюю папку в Codex как проект. Для команд нужен Python 3.11+.
3. В терминале этой папки выполните:

   ```powershell
   python scripts/check_starter.py --integrity
   python -m unittest discover -s tests -v
   python scripts/calculate_trip.py examples/trip-cost.json
   ```

4. Прочитайте [локальную настройку](docs/LOCAL_SETUP.md),
   [GitHub](docs/GITHUB_SETUP.md) и [гибридный процесс](docs/HYBRID_CODEX.md).
5. Начните с запроса: «Прочитай AGENTS.md. Используй $fleet-plan для MVP:
   организации, роли, машины, рейсы и плановая себестоимость. Составь первую
   вертикальную задачу с проверяемыми критериями приёмки».

## Шесть навыков

| Вызов | Когда применять |
|---|---|
| `$fleet-plan` | Превратить требование в ограниченную задачу и критерии |
| `$fleet-api` | Реализовать API с проверкой ролей, tenant и повторных запросов |
| `$fleet-ui` | Сделать диспетчерский интерфейс с понятными состояниями |
| `$fleet-data` | Менять модель данных, миграции и изоляцию организаций |
| `$fleet-costing` | Проверять план рейса, затраты периода, признанные доходы и финрезультат |
| `$fleet-release` | Проверять изменение, готовить PR и план выпуска |

Навыки лежат в проекте; устанавливать их глобально не требуется.
`.env.example` содержит пустые значения секретов. Пакет ничего не отправляет,
не создаёт облачных ресурсов и не меняет личные настройки Codex при распаковке.

## Происхождение и границы проверки

Ссылка на прошлую беседу позволила прочитать запросы, но не тексты прежних
ответов и не прежний ZIP. Этот комплект создан заново по текущему запросу.
Совпадение с прежним архивом не заявляется. Допущения перечислены отдельно.
Проверка целостности подтверждает байты поставки, а не готовность будущего SaaS.
После собственных изменений используйте обычный `check_starter.py`;
`--integrity` специально обнаруживает отличие от оригинального комплекта.
